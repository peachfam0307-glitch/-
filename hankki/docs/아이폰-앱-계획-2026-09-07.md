📌 아이폰 앱도 «같은 웹»이라 이 상태를 그대로 물려받는다 — 아이폰 따로 할 일은 없고, 위 ⑶이 «둘 다»의 선결이다.

## 9️⃣ 🔧 큰 틀 1 「바뀐 것만 읽기」 붙이기 — 설계 초안 (2026-09-07 08:25 · 코드 «안» 건드림 · 다음 세션이 바로 시작)

**🌲 코드 읽다 찾은 뿌리 (실측)** — `syncPull.js` 는 「고친때」를 문서 바깥 칸 `t` 로 올려 거르는 설계인데,
**앱 어디에서도 `고친때` 를 찍지 않는다** (`grep 고친때 src` = syncMerge·syncGrave·syncPull·cloud 주석뿐 · `store.jsx` 는 `savedAt` 만).
→ 그대로 붙이면 `t` 가 늘 0 → 「바뀐 것만」이 **영원히 0건** = 조용히 죽은 동기화. ⛔짐작으로 붙였으면 이렇게 됐다.

**✅ 고치는 모양 = 「고친때」 대신 «클라우드 시계»(`serverTimestamp`)를 바깥 칸 `st` 로**
| 자리 | 바꿀 것 | 왜 |
|---|---|---|
| `cloud.js` 올리기 `담기` | 값 `{ j: 글 }` → `{ j: 글, st: F.serverTimestamp() }` · 메타값에도 `st` | 폰 시계를 안 믿는다(기기마다 다름) · 서버가 찍으니 두 기기 비교가 됨 |
| `cloud.js` 내려받기 | 인자 `{ 이후, 메타문서 }` — `이후` 있으면 `query(collection, where('st','>',Timestamp.fromMillis(이후)))` · 없으면 지금처럼 통째로 · `메타문서` 받으면 meta 를 «다시 안 읽는다»(지금 2번 읽는 것 1번으로) · 돌려줄 때 `서버때 = meta.st.toMillis()` ＋ `부분인가` | 읽기 = meta 1 ＋ 바뀐 편 N |
| `cloud.js` 저절로받기 | `이후 = 마지막받은때읽기()` (새 칸 `hankki:cloud:pulledAt` · 숫자 ms) · **지문이 비어 있으면 통째로**(새 폰) · 합친 뒤 `지문맞추기(받은판, { 부분: true })` = 받은 id 만 갱신(⛔통째로 갈아끼우면 안 받은 편이 「안 올린 것」으로 둔갑) · `서버때` 있을 때만 `마지막받은때쓰기` · 계기판 `읽기 = 1 + 편수 (+ 무덤 1)` | 부분 받기여도 합치기는 «더하기»라 안전 — 안 받은 편은 내 것 그대로 |
| `지문지우기` · 로그아웃 | `pulledAt` 도 같이 지움 | 다른 사람으로 로그인하면 처음부터 |
| 수동 「가져오기」 | 그대로 통째로(`내려받기()` 인자 없음) | 옛 앱이 올린 `st` 없는 문서를 건질 유일한 길 |
| 재현판 셋 가짜 F(`_repro-자동받기붙이기-0904` · `_repro-폰패드왕복-0904` · `_repro-클라우드동기화-0821`) | `query`·`where`·`Timestamp.fromMillis`·`getDocs` 가 필터를 적용 · `serverTimestamp` 가 숫자 시계(지금은 ISO 문자열) | 판이 파이어베이스 없이 전부 돈다 |
| `_repro-바뀐것만-0904` | ⑪ **「st 없는 옛 문서는 통째로 받을 때만 온다」** ⑫ **「부분 받기 뒤 지문이 안 받은 편을 안 지운다」** 두 칸 추가 | 위 뿌리를 판이 지킨다 |

**⚠️ 세 각도 (설계 관문 미리)**
- 사람: 패드가 옛 판(st 안 찍는 앱)으로 올린 편은 폰의 «바뀐 것만»에 안 온다 → 창업자 두 기기가 같은 판으로 올라온 «뒤»에 실물 확인 · 유저는 전체 공개가 이 배포 «뒤»라 해당 없음
- 사고: 묶음이 여러 커밋으로 갈리면 편 `st` ≤ 메타 `st`(메타는 맨 마지막 할일) → 「메타 `st` 이후」로 다음에 받아도 빠지는 편 없음 · 받는 도중 상대가 올리면 다음 켤 때 온다(중복 읽기만 조금)
- 규모: 1만 명 × (meta 1 ＋ 무덤 1 ＋ 바뀐 편 ≈1) ≈ **3만/일** (무료 5만 안) · 지금 통째로 = 293만/일
- 잃던 것 → 잃을 것: 「200명에서 무료치 초과」 → 「옛 판이 올린 편은 수동 가져오기로만」
